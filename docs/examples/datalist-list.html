Aptus Datalist CSS — Row list

An alternative to .datalist-table built from ul > li with one real link per row. From 768px up, cells line up in columns under a header row; below that (max-width: 767.98px), each row becomes a native-app list item that spans the container edge to edge. Resize the window to compare both layouts.

Cell slots

Each .datalist-cell gets one slot class that decides where it goes on mobile:

ClassDesktopMobile
.datalist-titlecolumnline 1, left, bold, fills the space, truncated with ellipsis
.datalist-valueright-aligned columnline 1, right (before the badge)
.datalist-badgecolumnline 1, right
.datalist-subcolumnline 2, all subs on one line separated by "·"
.datalist-metacolumnline 3, smaller and more muted
.datalist-deskcolumnhidden

Add .is-empty to an empty cell: on desktop it keeps its column, on mobile it is hidden and does not leave a stray separator.

Column widths come from --datalist-cols on .datalist (any grid-template-columns value). .datalist-head and every .datalist-link share that grid. The header is visual only, so it is aria-hidden.

Quick actions

.datalist-actions sits outside the row link (interactive elements cannot be nested), as the second area of the li grid. Each .datalist-action is a round icon button with a 40px touch target and must have an aria-label. Actions are always visible, on desktop and mobile, so they are discoverable by touch and keyboard. When the list contains actions the column defaults to 48px and the header reserves the same width; set --datalist-actions-w for more buttons. Tab order: row link, then its actions.

Value column and meta line

.datalist-value is right-aligned on desktop (add the same class to its header span to align the label) and goes to the right of line 1 on mobile, before any badge. .datalist-meta becomes a smaller third line on mobile; .datalist-desk is hidden there.

Load more

.datalist-more centers the .datalist-more-btn button below the list. While loading, the script sets aria-busy="true" on the button (a spinner appears and clicks are ignored). When there are no more items, the script removes .datalist-more or sets hidden on it.

Tags

.datalist-tag is a neutral pill. Semantic modifiers: .datalist-tag-muted, .datalist-tag-success, .datalist-tag-warning, .datalist-tag-danger. Colors come from --datalist-tag-* variables.

Selection

.datalist-selectable on .datalist turns each li into [select] [link] [actions]. The label.datalist-select column (width --datalist-select-w, default 44px) is the touch target of the row checkbox; the header reserves the same width. Here the row body is a label.datalist-link pointing at the checkbox, so a click anywhere on the row toggles it (a row can also keep an a.datalist-link and navigate). .is-selected tints a selected row. The .datalist-selectbar sits before the rows with the "select all shown" checkbox (indeterminate while only some rows are selected), the count and the bulk actions. The checkbox states are wired by a script (Palatium DataList with selectable); here they are static.
